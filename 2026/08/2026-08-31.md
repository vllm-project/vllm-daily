### Summary

**What changed and why**  
This PR adds an alternative rendezvous mode for NCCL weight transfer that does not require a TCPStore, enabling torch-free trainers (e.g., JAX) to participate. It introduces an optional `nccl_unique_id_b64` field to `NCCLWeightTransferInitInfo`, a new classmethod `PyNcclCommunicator.from_unique_id_bytes`, and a helper `worker_init_payload` to serialize only the active rendezvous mode. **Technical impact**  
The change modifies the NCCL weight transfer initialization path by adding a new code path for unique-id-based rendezvous. It introduces validation logic to ensure exactly one rendezvous mode is set, adds a new communicator factory method, and refactors common initialization logic into `_init_comm`. The `repr` of the init info now hides the UID, which is a minor behavior change. The new code path is only worker-side; the trainer engine remains TCPStore-only, so torch-free trainers must drive rank 0 out of band.

**Key insights**  
The PR carefully maintains backward compatibility by keeping the existing TCPStore path intact and adding the unique-id path as an alternative. The validation logic is centralized in `decode_nccl_unique_id`, ensuring consistent error handling. The use of `kw_only` dataclass fields is a deliberate API hardening measure. ### Summary

**What changed and why**  
This PR fixes a security and performance issue in the validation exception handler where the error response body could become extremely large (up to ~5,300x amplification) by echoing the entire offending input for each validation error. The fix bounds the number of reported errors to 10, summarizes or truncates the input values, and cleans the loc field to remove verbose union type names, ensuring the response stays small and the handler runs quickly.

**Technical impact**  
The change modifies the validation error handler to cap the number of errors displayed and to replace large input values with size-bounded summaries. It also applies existing loc cleaning to the error loc. The true error count is still reported, and small inputs are preserved for legitimate debugging.

**Potential risks**  
The truncation and summarization of error inputs may reduce diagnostic detail for complex errors, though the most relevant information (field location and message) is retained. The new constants and helper functions are internal and could affect error message formatting for clients that parse the exact structure, but the format remains similar. There is a minor risk that the loc cleaning might alter the path for some edge cases, but tests cover union types. The change is app-wide, so all endpoints are affected, but the behavior is strictly bounded and should not break existing functionality.

**Key insights**  
The PR addresses a real amplification vulnerability where a small request can cause a massive response, leading to denial-of-service. The solution is pragmatic: cap the number of errors and summarize inputs rather than echoing them. The tests demonstrate the fix works and that small inputs are still shown verbatim, balancing security with usability. The change is well-scoped and includes clear documentation of the problem and solution.

### Summary

**What changed and why**  
This PR adds an opt-in feature to release NCCL communicator GPU memory during sleep mode using ncclCommSuspend/ncclCommResume. It introduces suspend/resume hooks on DeviceCommunicatorBase, implements them in CudaCommunicator and PyNcclCommunicator with idempotence guards, and orchestrates the calls in the GPU worker's sleep/wake_up methods, gated by a new --enable-nccl-comm-suspend flag (default False). The change preserves communicator identity while freeing ~1 GiB per rank, improving memory efficiency during sleep.

**Technical impact**  
Adds new NCCL library symbol bindings (ncclCommSuspend/ncclCommResume) with fallback for RCCL and older NCCL versions. Introduces a new ModelConfig flag and CLI argument, plus new functions suspend_device_comms/resume_device_comms in parallel_state. **Potential risks**

The code touches every sleep/wake call path, so there is risk of regressions in those flows, though tests cover several edge cases. FlashInfer workspaces are not released, and there is a known limitation with MNNVL transport in the test environment.

**Key insights**  
The PR carefully ships the feature opt-in to avoid affecting existing deployments. The idempotence guard in PyNcclCommunicator is a robust solution to the staged-wake double-resume crash. The design places orchestration in the worker layer rather than the allocator backend, avoiding layer inversion. The extensive testing, including token-exact output comparison and GSM8K accuracy checks, provides strong evidence of correctness. The deferral of FlashInfer workspace release is well-documented and justified by lack of a suitable primitive.
