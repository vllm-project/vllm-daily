- **Author:** [yuvalluria](https://github.com/yuvalluria)

- **Type:** `SUBSTANTIAL`
- **[Changed Files](https://github.com/vllm-project/vllm/pull/65987/files) (1):**
  - `vllm/model_executor/models/llama4.py`

### Summary

**What changed and why**  
Adds a conditional .contiguous() call on the sliced fused MoE expert weight tensor in load_moe_expert_weights in llama4.py, right before weight_loader() copies it to GPU. The transpose/chunk/indexing operations leave the tensor as a non-contiguous view, and DMA transfer of non-contiguous CPU tensors to GPU is much slower. The fix targets only the final sliced tensor to avoid inflating the contiguous copy size, based on a prior attempt that showed blanket .contiguous() can regress smaller tensors.

**Technical impact**  
Changes the memory layout of fused MoE expert weights passed to weight_loader, converting non-contiguous views into contiguous buffers before GPU transfer. The PR reports a measured ~20x speedup (574ms to 29ms) on an H100 NVL for a [64,4096,1024] tensor, which should meaningfully reduce Llama-4 model load time since MoE expert weights dominate checkpoint bytes. The change is gated on fused and isinstance(torch.Tensor) checks, limiting scope to the intended path.

**Potential risks**  
The benchmark is synthetic on a single H100 NVL because real Llama-4 checkpoints (109B-400B) don't fit on one GPU, so real-world gains are inferred rather than directly measured. Adding .contiguous() allocates an extra CPU buffer, temporarily increasing host memory usage during load, which could matter for memory-constrained hosts. The isinstance check is defensive but the fused flag gating means non-fused paths are unaffected; correctness depends on weight_loader accepting a contiguous copy identically to the prior view, which is expected but not explicitly tested here.

**Key insights**  
The fix is narrowly scoped and well-justified by measurement, correctly avoiding the blanket-contiguous regression noted in the earlier closed PR. The deliberate exclusion of FP8 block-scale and Q/K rotary permute locations, where .contiguous() was slower at smaller sizes, shows good empirical discipline. Main gap is lack of an automated regression test or real-checkpoint validation; a unit test asserting contiguity of the tensor passed to weight_loader would harden this against future refactors.

### Summary

**What changed and why**  
The PR makes the Rust DeepSeek DSML tool parsers (V3.2/V4/V4.1) stream tool-call arguments incrementally instead of emitting each call whole when it closes, addressing silent gaps that can trip client idle timeouts. It introduces a shared ArgumentsWriter/OpenToolCall in tool/arguments.rs that owns JSON syntax (separators, keys, escaping, keep-first duplicate keys, JSON validity checks), rewrites the DSML parser state machine to emit one delta per event, and adds ToolSchemas::is_verbatim_string to decide which schema-typed parameters may stream verbatim.

**Technical impact**  
Behavior changes beyond chunking: valid string="false" values now pass through as spelled rather than being coerced through the schema (e.g. 42 stays a number, null stays null), and repeated parameters keep their first value. String parameters stream as escaped JSON fragments; JSON-typed values are buffered and written once complete (as spelled if valid, as a JSON string otherwise); schema-typed values without a string attribute are converted once complete. Non-streaming output is the same state machine fed once, and roundtrip DSML output is byte-identical to the base.

**Potential risks**  
The pass-through of string="false" values diverges from prior schema coercion and from vLLM's default (no grammar constraint), so downstream consumers relying on coerced types may see different argument shapes. Malformed JSON fallback to string is a deliberate deviation from DeepSeek reference decoders. Known limitations: parse failures after a call starts streaming fall back to the chat layer's existing behavior, and truncated streams (finish_reason=length) leave partial arguments unrepaired. Validation lacks a run against a real model or engine, and one vllm-server test fails on main as well.

**Key insights**  
The design principle is that a value streams only where conversion is the identity for all text, leaving only JSON string escaping; JSON text is buffered because validity is known only at its end. The writer avoids building value trees (uses IgnoredAny) and serializes directly into a pending Vec<u8> for cheap deltas. Tests are thorough: per-chunk delta assertions, malformed-value handling, writer unit tests across split points and JsonStyle, and 1-character chunk streaming for V4.1. The open_raw_json path is dead code kept for future grammar-constrained formats.
