### Summary

**What changed and why**  
The DPX GPU lock acquisition in .buildkite/scripts/hardware_ci/run-amd-test.sh was changed from a non-blocking flock -n that failed immediately on collision to a blocking flock -w 600 that waits up to 10 minutes for the render-device lock. On timeout it now returns 134 instead of 1, and the caller uses a bare exit to propagate that code, relying on existing AMD pipeline retry behavior.

**Technical impact**  
CI jobs contending for the same DPX GPU will now queue on the lock rather than failing fast, reducing spurious collision failures. **Potential risks**  
Jobs can now block for up to 10 minutes, increasing queue latency and potentially hitting Buildkite timeouts if contention is high. The description mentions a 5s sleep between tries, but the diff shows a single flock -w 600 wait, so the described retry loop may not match the implementation. Exit 134 is SIGABRT-like and could be misinterpreted by tooling expecting a clean failure code.

**Key insights**  
The change is small but behaviorally meaningful for CI reliability. Verify that flock -w semantics match the stated retry/sleep design and that downstream retry handling correctly treats 134 as retryable. Consider whether a 10-minute wait is appropriate relative to overall job timeouts.

### Summary

**What changed and why**  
Fixes a tensor-parallel bug in DotsVisionAttention where the vision tower called Qwen2VisionAttention.split_qkv(), a helper designed for an all-gathered ColumnParallelLinear layout, on a QKVParallelLinear output that is already the local [q\\|k\\|v] shard. At TP>1 this scrambled q/k/v and produced degenerate repeated output. The fix replaces the helper call with a direct x.chunk(3, dim=-1) plus reshape, matching the glm_ocr.py pattern, and adds a skipped dots_ocr TP=2 entry to the VLM generation tests.

**Technical impact**  
Changes the vision attention QKV split path for dots.ocr and dots.mocr under weight-sharded TP. TP=1 behavior is unchanged since the old helper degenerated to the same local chunk(3). **Potential risks**

The vision tower also trips the GPU-sync checker at three host copies, an independent issue tracked separately.

**Key insights**  
Root cause is a layout mismatch between QKVParallelLinear (per-rank local shard) and the Qwen2-VL helper that assumes a gathered packed tensor, causing all-gather plus chunk(3) to interleave q/k/v across ranks. The data-parallel encoder mode was unaffected, which cleanly isolates the defect to the weight-sharded ViT. Validation is thorough across two backends with byte-identical TP=2 vs TP=1 output, but the skipped test means the intended TP>1 coverage is recorded rather than enforced.

## 10. [[Multimodal] Refactor encoder cuda graph to support share graph buffer reuse](https://github.com/vllm-project/vllm/pull/65084)


### Base Information

- **PR Number:** #65084
- **Author:** [Isotr0py](https://github.com/Isotr0py)
- **Merged By:** [shen-shanshan](https://github.com/shen-shanshan)
- **Merged time:** 2026-11-07 18:22:11
- **Type:** `SUBSTANTIAL`
- **[Changed Files](https://github.com/vllm-project/vllm/pull/65084/files) (3):**
  - `docs/design/cuda_graphs_multimodal.md`
  - `tests/v1/cudagraph/test_encoder_cudagraph.py`
  - `vllm/v1/worker/encoder_cudagraph.py`

### Summary

**What changed and why**  
Refactors encoder CUDA graph capture so that all token budgets within a (path, capture-axis) group share one max-size set of input and output buffers via prefix views, instead of each budget allocating its own full buffers. It also replaces the power-of-2 default budget ladder with a subdivided grid (quarter-octave up to 1024, half-octave above) and adds exact item-multiple budgets for paths with fixed-size items, reducing padding waste from ~33% to ~10% at roughly constant buffer memory.

**Technical impact**  
Buffer memory for encoder graphs drops from O(sum of budgets) to ~1x the largest budget, making the denser default table affordable; capture time rises modestly (one extra forward per extra tier, ~+7s on DSV4.1 TP=4) while total capture memory actually decreases. The sharing is generic and requires no model changes: incompatible buffers fall back to per-budget allocation, and scalars are shared by identity. Default budget tables and per-path budget generation change for all encoder-CG models, which is a behavior change beyond the buffer refactor.

**Potential risks**  
Correctness depends on the invariant that encoder buffers are packed-contiguous row buffers and replay only writes buf[:real_rows]; any model whose capture inputs or outputs violate prefix compatibility (e.g., non-row-major or shape-varying trailing dims) silently falls back, which is safe but may reintroduce memory cost. Sharing output buffers across graphs means a stale or oversized write could contaminate later replays, so the large-then-small replay test is important. The denser default table increases graph count (25 vs 9), raising capture-time cost and memory for graph metadata, and could interact with capture-axis multiplication; the existing 64-graph warning is the only guard. The new budget generation logic (grid and item-multiple) is more complex and needs careful validation for edge ranges.

**Key insights**  
The PR cleanly decouples budget granularity from buffer memory by reusing the decoder's input_ids[:num_tokens] prefix-view pattern, which is a sound and low-risk design given the packed-row-buffer assumption. The fallback path for incompatible buffers is a good safety net, and the added tests (shared storage, prefix views, replay equivalence, fallback, clear) cover the key invariants. Deletes mtp_validation.py and its tests, removes per-loader completeness validation from DeepSeek family, glm5next, kimi_k3, bailing, minimax_m3, step3p5, step5, inkling, hy_v4, qwen3_dspark, muse_spark, lilicorr, llama_eagle3, qwen3_eagle3, qwen3_xpress, plus AliceAI, Nemotron audio, Parse 3.5 RADIO LayerScale, MuseSpark Quark experts, dots3 FP8 indexer, and AutoWeightsLoader tied-alias checks. Confidence-head deletion on missing weights is removed so config alone decides existence. IPC, M2N, and NCCL engines drop the context manager wrapping. Adds weight_update_active() to reload lifecycle and a new test_reload_lifecycle.py covering direct and layerwise modes and nested modules.

**Potential risks**  
Deliberate behavior change: missing draft/main/encoder weights, missing d2t mappings, tied-embedding alias-only checkpoints, and partial FP8 indexer updates now silently leave weights at initial values instead of raising, which can produce wrong outputs or low acceptance rates rather than errors. The process-wide flag is not thread-local and is not reset on exceptions in start_reload/finish_reload, so a failed reload could leave it stuck True and suppress cold-start checks; tests patch it manually. Several paths (MiniMax M3 MTP, layerwise updates on full models, AliceAI/Nemotron/Parse/MuseSpark/dots3 full models, IPC/M2N on full models) were not exercised end-to-end.

**Key insights**  
The change trades fail-fast validation for tolerance of bucketed updates, which is reasonable given the false-positive problem, but it shifts failure modes from loud errors to silent quality degradation. The weight_update_active() flag is a coarse process-wide signal rather than per-call context, so correctness depends on start_reload/finish_reload always pairing; the PR notes follow-up checks by checkpoint name and cold-start draft checks are planned. Test plan shows parity with main on GSM8K and acceptance across several architectures, but coverage gaps remain for quantized checkpoints missing draft weights and several full-model paths.

### Summary

**What changed and why**  
Bumps ruff from v0.14.0 to v0.17.2 in pre-commit and enables previously ignored rules UP032, UP042, B007, F403 and F405, applying the resulting fixes across ~286 files. Fixes include f-string conversions, (str, Enum) to StrEnum migrations, unused loop variable renames, explicit imports replacing star imports, and removal of now-redundant noqa comments. It also fixes real bugs: undefined names in vllm/model_executor/kernels/mhc/__init__.py __all__ and two SIMPLE_PROMPT 1-tuple bugs in test_accuracy.py files.

**Technical impact**  
Behavior changes are mostly cosmetic but not entirely: UP042 converts 21 enum classes to StrEnum, which changes str()/format() output of members (e.g. AttentionType.DECODER renders as 'decoder'), affecting error and log messages. Replacing star imports with explicit imports in benchmark_moe.py and mhc/__init__.py changes the public surface of those modules, and the mhc fix repairs a previously broken 'from ...mhc import *'. The ruff-format hook is restricted to python/pyi/jupyter to avoid v0.16 formatting Markdown code blocks and mangling '--8<--' snippet syntax.

**Potential risks**  
StrEnum migration could silently alter any downstream code relying on str(enum_member) or f-string formatting of these enums, including log parsing, metric labels, or serialized payloads; the PR claims an audit found only message text affected, but this is hard to fully verify. Explicit import lists replacing star imports may drop names that external code or benchmarks implicitly relied on. The large mechanical diff (286 files) raises review fatigue and risk of subtle accidental edits. Validation was partial: only 56 of 109 touched test files pass locally, with failures attributed to environment or pre-existing issues, so CUDA-only paths depend on CI.
