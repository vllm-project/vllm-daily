## 1. [[CPU][GDN] Support NIXL DS convolution-state layout](https://github.com/vllm-project/vllm/pull/53300)


### Base Information

- **PR Number:** #53300
- **Author:** [tianmu-li](https://github.com/tianmu-li)
- **Merged By:** [bigPYJ1151](https://github.com/bigPYJ1151)
- **Merged time:** 2026-09-23 23:55:21
- **Type:** `SUBSTANTIAL`
- **[Changed Files](https://github.com/vllm-project/vllm/pull/53300/files) (4):**
  - `tests/kernels/mamba/cpu/test_cpu_gdn_ops.py`
  - `tests/platforms/test_cpu.py`
  - `vllm/model_executor/layers/mamba/ops/cpu/gdn_attention.py`
  - `vllm/platforms/cpu.py`

### Summary

**What changed and why**  
This PR makes CPU GDN convolution and recurrent-state handling compatible with both the NIXL-required DS physical layout ([conv_dim_local, conv_rows]) and the existing SD layout. It adds automatic DS layout selection in CpuPlatform.check_and_update_config when a NIXL connector is configured, introduces staging/scatter adapters in gdn_attention.py that materialize dense-inner-stride views before calling native CPU kernels, and removes the previous SD-only assertions/fallbacks across prefill, decode, speculative, and multi-token update paths. Tests were extended to cover layout selection and DS/SD equivalence.

**Technical impact**  
Behavior changes in CPU platform config (env var VLLM_SSM_CONV_STATE_LAYOUT now defaults to DS for NIXL connectors, SD otherwise on AVX-512BF16 CPUs) and in the GDN attention dispatch path, which now transparently handles both layouts via index_select/index_copy_ staging. Native conv.cpp is invoked with identity indices on a scratch buffer for DS, then results are scattered back, so existing SD callers are unaffected while DS callers no longer hit RuntimeErrors. Reported perf impact is a modest ~1.46% throughput drop for DS versus SD, with identical accuracy.

**Potential risks**  
The DS adapter adds an extra index_select/copy and a scatter per conv call, which could regress latency in hot decode paths beyond the measured throughput delta, especially for large state sizes or many slots. Correctness depends on state_indices being valid and unique; duplicate or out-of-range indices could cause incorrect scatter semantics. The env-var-based layout selection is process-global and set during config check, so mixed-layout scenarios or late config changes could be inconsistent. Test coverage relies on monkeypatching is_conv_state_dim_first and ops, so real native-kernel DS behavior is only partially exercised.

**Key insights**  
The design cleanly separates layout concerns from kernel logic by staging DS states into an SD-compatible scratch buffer with identity indices, avoiding invasive changes to conv.cpp. Automatic DS selection for NIXL is gated on connector name detection and respects an explicit user override, which is a sensible precedence. The removal of prior RuntimeError guards is safe only because the new adapters cover all previously guarded call sites, so reviewers should verify no remaining direct ops.causal_conv1d_* calls bypass the wrappers. The PR is well-tested at the Python level but would benefit from an end-to-end NIXL CPU run to validate the full transfer path.

## 2. [[Compile][CI] Honor Triton cache overrides and add AMD timeout headroom](https://github.com/vllm-project/vllm/pull/58474)


### Base Information

  - `.buildkite/test_areas/model_executor.yaml`
  - `docs/design/torch_compile.md`
  - `vllm/compilation/compiler_interface.py`

### Summary

**What changed and why**  
The InductorAdaptor.initialize_cache method now preserves an explicitly configured TRITON_CACHE_DIR instead of always overwriting it with a model-local triton_cache subdirectory, using a module-level _last_inductor_triton_cache_dir to distinguish caller overrides from previously assigned defaults. Two Buildkite pipeline definitions raise the AMD Model Executor timeout from 60 to 75 minutes, and docs/design/torch_compile.md documents cache population, export, and cold-cache isolation behavior. This was motivated by PR #58092 enabling MRV2 sampler warmup, which exposed heavy kernel compilation overhead in CI and caused jobs to exceed the 60-minute budget.

**Technical impact**  
Processes and model configurations that share an externally supplied TRITON_CACHE_DIR can now reuse compiled Triton kernels instead of recompiling per model configuration, reducing CI compile time. The global _last_inductor_triton_cache_dir tracks the last adaptor-assigned path so that a subsequent model without a caller override still gets its own model-local triton_cache, preserving Inductor graph cache separation. The timeout bump gives AMD jobs additional headroom while keeping the existing 900-second pytest watchdog.

**Potential risks**  
The global mutable state _last_inductor_triton_cache_dir is process-wide and not thread-safe; concurrent or interleaved adaptor initializations could misclassify a caller override as a stale default or vice versa. If a caller sets TRITON_CACHE_DIR to a path that happens to equal the last assigned default, it will be treated as a default and replaced, which is an edge case. Sharing a Triton cache across differing model configurations could theoretically surface stale or incompatible kernel artifacts if cache keys are insufficiently discriminating, though Triton keys are generally robust. The timeout increase may mask underlying performance regressions rather than fixing them.

**Key insights**  
The change correctly separates caller-provided Triton cache overrides from adaptor-assigned defaults, enabling cross-configuration kernel reuse without introducing a new environment variable or requiring cache prepopulation. The reliance on a module-level global to detect prior assignments is the main fragility and would benefit from a more explicit mechanism, such as tracking ownership per adaptor instance or a sentinel. The timeout and cache changes are independent mitigations for the same CI symptom, and the documentation update appropriately clarifies cold-cache isolation expectations for tests.
