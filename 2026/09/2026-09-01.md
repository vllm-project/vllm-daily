The fix modifies the regex in deepseek_v4.py to implicitly close a parameter when the next parameter start tag is encountered, and adds the PARAM_START token to the parser engine configs for both DeepSeek V4 and V3.2. Tests were added to cover non-streaming and streaming scenarios, including chunk-boundary splits.

**Technical impact**  
The change alters the core parsing logic for DeepSeek tool calls, making the parser more robust against malformed input. It introduces a new token (PARAM_START) to the engine config, which may affect tokenization and streaming behavior. The regex change uses a lookahead to detect the next parameter start, which could have performance implications on large inputs, though likely negligible. The fix applies to both DeepSeek V4 and V3.2, ensuring consistent behavior across models.

**Potential risks**  
The implicit close behavior might incorrectly terminate a parameter value that legitimately contains the substring '<｜DSML｜parameter name=' (e.g., in a string value). The new test 'test_implicit_close_preserves_malformed_text' suggests that malformed text is preserved, but the regex change could alter parsing of edge cases where parameter values contain XML-like markup. Additionally, the change to the regex may affect partial parsing and streaming buffering, potentially introducing regressions in other scenarios not covered by tests.

**Key insights**  
The PR addresses a real-world robustness issue in LLM tool calling, where models often omit closing tags. The solution leverages the structure of DSML to infer parameter boundaries, which is a pragmatic approach. The extensive test plan, including chunk-boundary invariance tests, demonstrates a thorough validation effort. The change is minimal (4 lines in production code) but has a significant positive impact on parser reliability.
