## 1. [[CI] Only isolate the registry tests that need a fresh process](https://github.com/vllm-project/vllm/pull/58764)

- **Type:** `SUBSTANTIAL`
- **[Changed Files](https://github.com/vllm-project/vllm/pull/58764/files) (1):**
  - `tests/models/test_registry.py`

### Summary

**What changed and why**  
The PR refactors tests/models/test_registry.py to stop isolating every registry test in a fresh process. It removes the create_new_process_for_each_test decorator and the init_cuda parameter from the property and is_pp tests, and introduces a dedicated test_registry_inspect_does_not_init_cuda test that keeps process isolation only for the two architectures (LlavaForConditionalGeneration, Qwen2VLForConditionalGeneration) that initialize CUDA on import. The motivation is CI performance: on ROCm, spawn-based isolation costs ~15s per test, and the MI300X runtime reportedly drops from 325.60s to 161.01s.

**Technical impact**  
Behavioral coverage is preserved for the CUDA-init-on-import check via the new isolated test, while the remaining property assertions now run in-process, which is faster and still valid because they only perform metadata inspection. The init_cuda column is removed from parametrization, simplifying the test matrix. The new test skips on non-CUDA-like platforms, so the CUDA-specific assertion only runs where it is meaningful.

**Potential risks**  
The new test only covers two architectures, so if other models later start initializing CUDA on import, the regression would no longer be caught by the property tests. Running the property tests in-process could theoretically be affected by import side effects from other tests in the same worker, though inspection is intended to be side-effect free. The skip on non-CUDA platforms means the CUDA-init assertion is not exercised in CPU-only CI.

**Key insights**  
This is a targeted CI optimization that trades broad process isolation for a single focused isolated test, cutting AMD CI time roughly in half. The key correctness argument is that only import-time CUDA initialization requires a fresh process, and that concern is now explicitly tested. Reviewers should confirm the two listed architectures are the only ones with import-time CUDA init and that in-process inspection remains free of global state mutation.

### Summary

**What changed and why**  
The PR fixes a bug where the Inkling tool/function name leaked into streamed delta.content when a tool call followed a reasoning block. The root cause was that THINK_END emitted REASONING_END immediately, causing the two-pass DelegatingParser to hand off to the tool pass before the next block opener, so the function-name header after <\\|message_model\\|> was emitted as content. The fix defers REASONING_END for THINK_END inside a reasoning block, relying on the next typed opener (MESSAGE_HEADER) to emit it, while END_SAMPLING still ends reasoning immediately.

**Technical impact**  
Changes the state machine transition for (REASONING, THINK_END) in inkling_config from emitting REASONING_END to emitting no events, altering parser engine behavior for reasoning-to-tool handoff. A new regression test TestDelegatingTwoPass::test_function_name_not_in_content_after_reasoning verifies the function name no longer appears in content and that reasoning, tool names, and args are correctly parsed. This affects the two-pass DelegatingParser flow used with --reasoning-parser inkling --tool-call-parser inkling.

**Potential risks**  
Deferring REASONING_END could cause reasoning to remain open longer than expected if no subsequent typed opener arrives, potentially affecting edge cases such as truncated streams or streams ending right after THINK_END without a following block. The change is narrowly scoped to THINK_END within REASONING state, but any downstream consumer relying on immediate REASONING_END emission at THINK_END could see timing differences. Test coverage is limited to the specific scenario described, so other reasoning/tool interleavings may warrant additional verification.

**Key insights**  
The bug stems from an ordering/timing issue in a two-pass delegating parser where an early REASONING_END triggers a premature handoff to the tool pass. The fix leverages the existing MESSAGE_HEADER opener to emit REASONING_END at the correct point, keeping the function-name header out of content. The PR includes a targeted regression test that fails before and passes after, with 142 passed and 2 skipped, indicating a focused and well-tested fix.
